사용자가 `/local-test`를 호출했다. 로컬 개발 서버(`http://localhost:3000`)를 대상으로 대상 화면에 진입해 통합 테스트를 수행한 뒤, **테스트 결과 리포트만** 반환한다.

> ⚠️ **소스 코드를 절대 수정하지 않는다.** 오직 화면 진입, 렌더링 검사, 콘솔 에러 확인, 인터랙션 테스트만 수행한다.

## 인자

1. **진입할 화면 URL**: (예: `/`, `/map`, `/search`, `/saunas/new`, `/my` 또는 특정 사우나 상세 경로)

## 절차

### 1. 개발 서버 준비 (Health 체크)
- 먼저 `http://localhost:3000`이 응답하는지 확인한다.
- **이미 서버가 켜져 있으면(`pnpm dev`) 그대로 재사용한다** (중복 프로세스 기동 방지).
- 실행 중이 아니라면 백그라운드로 `pnpm dev`를 기동하고 응답할 때까지 대기한다.

### 2. 브라우저 진입 및 동작 검증
- 지정된 대상 URL(`http://localhost:3000{path}`)로 진입한다.
- **화면 렌더링 확인**:
  - 모바일 프레임(`<AppFrame>`) 및 메인 콘텐츠가 정상 노출되는지 확인.
  - 폰트 깨짐이나 스타일 레이아웃 시프트(CLS), FOUC 현상이 없는지 확인.
- **네트워크 & 콘솔 확인**:
  - 4xx/5xx 실패 네트워크 요청이 있는지 확인.
  - 브라우저 콘솔의 React Hydration 에러나 Uncaught Exception이 있는지 확인.
- **주요 버튼 인터랙션**:
  - 필터 칩 클릭, 탭 전환, 검색어 입력 등 주요 인터랙션을 실행하고 에러가 없는지 관찰.

### 3. 결과 리포트 출력

```markdown
## 🧖‍♂️ 로컬 통합 테스트 결과

- **대상 화면**: {url}
- **진입 상태**: {성공 / 실패}

### 1. 콘솔 및 네트워크
- 실패 API / 네트워크: {없음 / URL + 상태 코드}
- 콘솔 에러 / 경고: {없음 / 내용}

### 2. 화면 노출 및 레이아웃
- {정상 노출 / 이상 현상 설명}

### 3. 인터랙션 동작
- {테스트한 요소}: {정상 동작 / 비정상 동작}

### 4. 종합 평가
- **결과**: {PASS / FAIL}
- **요약**: {핵심 요약 1~2줄}
```

## 🚫 중요: 서버 기동 불가 시 즉시 중단
포트 충돌이나 서버 자체 기동 실패 시 복잡한 디버깅을 시도하지 않고 즉시 원인을 보고하고 종료한다.
