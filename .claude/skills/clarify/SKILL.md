사용자가 `/clarify`를 호출했다. 직전 메시지(또는 이 명령 뒤에 동봉된 텍스트)가 길거나, 여러 의도가 섞여 있거나, 모호한 부분이 있을 가능성이 높다. **작업을 바로 시작하지 말고**, 아래 절차를 따른다.

## 절차

1. **원문에서 핵심을 추려서 아래 4가지 항목으로 재진술**한다. 원문에 없는 정보는 추가하지 말고, 불확실한 부분은 그대로 "불확실"로 남긴다.

   - **의도 (Goal)**: 사용자가 궁극적으로 얻고 싶은 결과 한 문장
   - **범위 (Scope)**: 건드릴 대상 / 건드리지 않을 대상
   - **제약 (Constraints)**: 지켜야 할 규칙, 우선순위, 금지 사항
   - **산출물 (Deliverable)**: 결과물의 형태 (코드 변경 / 답변 / 파일 / 명령 등)

2. **모호하거나 누락된 부분**이 있으면 번호 매긴 질문 1-3개("1) 2) 3)" 형식)로 정리해서 사용자에게 묻는다.

3. 사용자의 확인 또는 답변이 올 때까지 **코드 수정·파일 작성·외부 호출 등 어떤 변경 작업도 시작하지 않는다**. 읽기/조사 작업은 재진술의 근거를 확인하기 위해 필요한 경우에 한해 허용한다.

4. 사용자가 "OK / 맞아 / 진행해" 류의 확답을 주면 그제서야 작업에 착수한다.

## 출력 형식 예시

```
## 요약
- 의도: ...
- 범위: ...
- 제약: ...
- 산출물: ...

## 확인 필요
1) ...
2) ...

이대로 진행하면 될까요?
```

## 인자

명령 뒤에 텍스트가 붙어 있으면 그 텍스트를 우선 대상으로 삼고, 비어 있으면 직전 사용자 메시지를 대상으로 한다.
